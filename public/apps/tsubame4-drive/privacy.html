TSUBAME4 Drive Storage

Privacy policy

Effective and last updated: October 26, 2026

OverviewPrivacy policyTerms of use

TSUBAME4 Drive Storage is a personal Google Drive mounting setup operated by Taishiro Wakamiya using google-drive-ocamlfuse on TSUBAME4. This policy describes the Google user data handled by that setup and this information website.

Data accessed

  • Google Drive file contents and metadata needed for requested filesystem operations, including file names, identifiers, parent folders, sizes, timestamps, and permissions.
  • Google account and storage information returned by the Drive API to identify the authorized account and report available storage.
  • OAuth access and refresh tokens that permit the client to perform authorized operations without asking the owner to sign in for every request.
  • Operational logs, cached file data, and filesystem metadata needed to run and troubleshoot the mount.

Purpose and use

Google user data is used to provide the owner's requested file browsing, transfer, storage, and file management operations, and to maintain the connection. The normal directory tree starts at a configured folder; the client also provides a virtual .shared view of items shared with the account. The OAuth grant permits access to Google Drive more broadly.

Google user data is not sold, used for advertising, or used to train generalized AI or machine learning models. Use and transfer of data obtained from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements.

Storage and protection

Cloud files are stored in the owner's Google Drive account. Credentials, metadata, logs, and a working file cache are stored in private directories on TSUBAME4. Files accessed through the owner's Google Drive desktop client may also be cached on that computer.

Google API traffic uses HTTPS. TSUBAME4 credential and state files are restricted to the owning operating system account, with private directory permissions. The owner remains responsible for protecting their devices, credentials, and institutional account. Authorized infrastructure administrators may have access according to the relevant service's operational policies.

Transfers and service providers

Requested transfers take place between Google Drive and the owner's authorized computers and TSUBAME4 environment. The mounting setup does not intentionally disclose Drive data to other recipients unless the owner requests a file operation that does so.

This public information website is hosted by GitHub Pages. It does not receive OAuth tokens or Drive files and uses no application analytics or tracking scripts. GitHub may process ordinary web request information under its privacy statement. Google's services are subject to Google's privacy policy.

Retention and deletion

Drive files remain in the owner's account until the owner changes or deletes them. Normal deletion through the configured mount moves files to Google Drive's trash. Cache entries are removed according to the client's cache management settings. Pending transfers and active files may require additional working storage.

Authentication state, metadata, and operational logs remain on TSUBAME4 until replaced or removed by the owner. To remove the setup, the owner can unmount it and remove its credentials, metadata, logs, and cache directories after confirming that needed files have reached Drive.

Revoking access

The owner can revoke TSUBAME4 Drive Storage's access at any time through Google Account third-party connections. They should then unmount the filesystem and remove saved credentials if the setup is no longer needed. Revoking access does not delete files already stored in Google Drive.

Contact and updates

Contact the maintainer through the owner's GitHub profile or the website issue tracker. Public issues should contain no credentials or private file contents. Changes to this policy will be published here with a revised date.
